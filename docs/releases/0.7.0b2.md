# PyTradeKit 0.7.0b2 - Metrics, Tracing & Alerting

**Status:** Beta milestone - LOT-06.

PyTradeKit 0.7.0b2 makes security, safety, health, and runtime failures observable and actionable without making telemetry part of economic truth.

Implemented:

- Low-cardinality labeled metrics using the existing RuntimeMetrics registry.
- authorization_decisions_total and authorization_denied_total.
- safety_decisions_total, kill-switch, risk-override, and dangerous-confirmation metrics.
- health_component_status, health_check_failures_total, and readiness_transitions_total.
- alerts_created_total, alerts_resolved_total, and alert_delivery_failures_total.
- TraceContext and TraceRecord with CorrelationId and CausationId propagation.
- TraceRecorder with fail-safe exporter semantics.
- OpenTelemetry-compatible adapter through an injected tracer.
- AlertId, AlertType, AlertSeverity, AlertState, and Alert.
- AlertRepositoryPort, AlertRouterPort, AlertSinkPort, and TraceExporterPort.
- Stateful alert deduplication, acknowledgement, verified resolution, and delivery routing.
- Health-to-alert evaluation for database, broker stream, and reconciliation conditions.
- In-memory, runtime-event, and deterministic failing alert adapters.

Critical guarantees:

- Repeated critical conditions create one unresolved alert per deduplication key.
- Sink failure never erases the open alert.
- Metric labels reject UUID-like high-cardinality values.
- Secret-like values are rejected from events, labels, traces, and alerts.
- Trace exporter failure cannot change the application result.
- Observability does not mutate trading aggregates.
- LIVE remains unavailable.
