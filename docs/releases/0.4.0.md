# PyTradeKit 0.4.0 - Strategy & Backtest Runtime

## Release message

PyTradeKit 0.4.0 introduces a broker-agnostic strategy runtime and deterministic historical backtesting while preserving one canonical trading core.

The release proves that Strategy, Risk, OMS, ExecutionReport, Fill, and Portfolio can be composed for historical simulation without creating backtest-specific duplicates of those domains.

## Safety and correctness guarantees

The qualified 0.4 implementation enforces:

- Signal is distinct from TargetPosition
- TargetPosition is distinct from OrderIntent
- OrderIntent is distinct from canonical Order
- Strategy does not receive broker or ExecutionPort access
- Strategy callbacks receive one event at a time rather than future-indexable history
- BacktestClock advances only under runtime control
- historical dataset checksum is verified before iteration
- historical events must be strictly ordered
- orders are evaluated only against strictly future eligible market events
- MARKET fills use the future bar open under the P0 execution model
- BUY LIMIT requires future bar low <= limit
- SELL LIMIT requires future bar high >= limit
- slippage, cost, and latency are explicit models
- simulated execution implements the existing ExecutionPort
- pre-trade Risk remains the milestone 0.3 Risk implementation
- OMS remains the milestone 0.2 Order implementation
- canonical Fill remains the source of Portfolio mutation
- RunManifest records the semantic inputs required for replay
- the Golden Backtest produces stable expected economics
- two identical deterministic runs produce equal semantic reports

## Explicit limitations

0.4.0 does not include:

- real broker connectivity
- durable database persistence
- process-restart recovery
- reconciliation against broker snapshots
- corporate-action processing
- multi-currency FX conversion
- order-book depth or queue simulation
- advanced partial-fill simulation
- HTTP API
- distributed workers
- production operations

These remain later roadmap milestones.

## Upgrade from 0.3.0

0.4.0 preserves the 0.3 Portfolio and Risk semantics and adds Strategy, Market Data, and Backtesting as bounded package surfaces.

Existing 0.1 through 0.3 public APIs remain available.

The package root remains intentionally narrow and continues to expose only __version__.
