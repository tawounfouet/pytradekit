# PyTradeKit 0.3.0 - Portfolio & Risk

## Release message

PyTradeKit 0.3.0 gives canonical economic meaning to execution fills and adds a deterministic pre-trade risk boundary before broker submission.

The release introduces portfolio accounting, valuation, projected portfolio risk, P0 risk limits, scoped trading halts, and application integration between Orders, Portfolio, Risk, and Execution.

## Safety and correctness guarantees

The qualified 0.3 implementation enforces:

- actual positions change only from canonical fills
- duplicate fills produce one portfolio economic effect
- signed position quantity determines LONG, SHORT, or FLAT state
- full close removes average entry price
- position flips reset the entry price to the flip fill price
- realized PnL is recognized only on closed quantity
- pre-trade risk evaluates projected portfolio state without mutating actual state
- MARKET risk evaluation requires a reference price
- LIMIT risk evaluation uses the limit price
- missing portfolio state or required price fails safe for risk-increasing actions
- a Risk REJECT result prevents any call to ExecutionPort.submit
- an active trading halt blocks risk-increasing orders
- an active halt can allow explicit reduce-only actions when policy permits
- Portfolio and Risk domains remain broker independent
- Orders domain remains independent from Risk
- persistence frameworks do not leak into Portfolio or Risk domain code

## Explicit limitations

0.3.0 does not include:

- real broker connectivity
- durable database persistence
- process-restart recovery
- reconciliation against broker snapshots
- strategy runtime
- backtest runtime
- foreign-exchange conversion for multi-currency portfolio valuation
- margin models beyond the milestone leverage primitives
- HTTP API
- distributed workers
- production operations

These remain later roadmap milestones.

## Upgrade from 0.2.0

0.3.0 preserves the 0.2 OMS and Execution semantics and adds Portfolio and Risk as bounded package surfaces.

SubmitOrder remains backward compatible when no RiskEvaluationPort is configured.

When pre-trade risk is configured, account context and the required pricing context must be supplied. A rejected order remains pre-submission and no broker call is made.

The package root remains intentionally narrow and continues to expose only __version__.
