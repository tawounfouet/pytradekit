**Status:** Beta milestone in progress - LOT-05.

0.8.0b1 begins the real IBKR Anti-Corruption Layer implementation.

## LOT-05.1 - Provider Primitives & Identity Model

Added:

- IBKRClientId for runtime API client identity;
- IBKRSessionOrderId for session-scoped order routing;
- IBKRPermanentOrderId for non-zero permId;
- IBKROrderReference for orderRef correlation;
- IBKRExecutionId for provider execution observations;
- IBKRContractId for qualified conId;
- IBKRConnectionIdentity;
- IBKROrderIdentity;
- IBKRExecutionIdentity;
- IBKRExecutionCorrection;
- IBKRContractIdentity;
- conflict-safe IBKROrderIdentityRegistry.

## Identity invariants

~~~text
orderId != permId
clientId + orderId = provider routing key
permId = stable external order identity candidate
orderRef = client correlation
execId = execution observation identity
conId = provider instrument identity
~~~

ProviderOrderIdentity cannot be emitted until a non-zero permId has been observed.

A bound permId cannot be silently changed.

Execution correction identity is represented explicitly without creating economic Fill semantics inside the provider identity layer.

## LOT-05.2 - Contract & Instrument Mapping

Added:

- SDK-free IBKRContractRecord and IBKRContractDetailsRecord;
- IBKRInstrumentMappingResult;
- conId mapping into ProviderInstrumentIdentity and InstrumentMapping;
- STK / SMART / USD mapping into canonical EQUITY Instrument;
- minSize mapping into ContractSpecification.min_quantity;
- sizeIncrement mapping into ContractSpecification.quantity_step;
- preservation of primary exchange, local symbol, trading class, order types and time zone metadata;
- marketRuleIds-aware price increment semantics.

When marketRuleIds are present, reported minTick remains provider metadata and canonical tick_size stays unknown. This prevents a provider minimum increment from being misrepresented as a universal static tick.

LOT-05.2 adds no provider SDK dependency, performs no network call and makes no PAPER certification claim.

## LOT-05.3 - Order Command Mapping

Added:

- SDK-free IBKROrderCommand and IBKRPlacementCommand;
- BUY / SELL action mapping;
- MARKET / LIMIT to MKT / LMT mapping;
- DAY-only time-in-force enforcement;
- client_order_id to orderRef correlation mapping;
- explicit TRANSMIT policy;
- regular-hours-only, non-what-if and non-override safety defaults;
- pre-transport quantity and static tick validation;
- Decimal-preserving command representation.

The mapper accepts only canonical orders already in SUBMITTED state and rejects orders that already have an external_order_id.

nextValidId and provider session orderId allocation remain transport/runtime responsibilities.

LOT-05.3 adds no provider SDK dependency, performs no network call and makes no PAPER certification claim.

## LOT-05.4 - Order Status & Callback Normalization

Added:

- SDK-free openOrder, orderStatus and order-scoped error observations;
- explicit status rules for PendingSubmit, PreSubmitted, Submitted, PendingCancel, ApiCancelled, Cancelled, Filled and Inactive;
- ProviderOrderStateSnapshot normalization for cumulative provider state;
- callback ordering support through the provider-local identity registry;
- explicit error 201 to REJECTED mapping;
- explicit error 202 to CANCELLED mapping;
- sanitized canonical rejection reason text.

PendingCancel is never treated as terminal cancellation.

Filled and cumulative partial-fill state never create a synthetic Fill. They require execDetails before a canonical economic execution can be emitted.

Inactive and unknown provider states require reconciliation and never default to REJECTED.

LOT-05.4 adds no provider SDK dependency, performs no network call and makes no PAPER certification claim.

## LOT-05.5 - Execution Details & Fill Mapping

Added:

- SDK-free IBKRExecutionDetailsObservation;
- IBKRExecutionRegistry with NEW, DUPLICATE and CORRECTION dispositions;
- execId mapping into ProviderFillIdentity and Fill.external_fill_id;
- deterministic canonical FillId generation from provider execution identity;
- shares mapping into Fill.quantity;
- execution price mapping into canonical Price;
- cumQty-based PARTIALLY_FILLED versus FILLED status selection;
- explicit BOT / SLD correlation with canonical BUY / SELL;
- conId, symbol, orderRef and permId consistency checks;
- pendingPriceRevision fail-closed handling;
- provider execution timestamp parsing with real timezone conversion to UTC.

Exact execId replay produces no second economic effect.

Execution corrections in the same execId family require reconciliation and never become a second independent Fill.

Commission is not fabricated from execDetails and Fill.fee remains None.

LOT-05.5 adds no provider SDK dependency, performs no network call and makes no PAPER certification claim.
