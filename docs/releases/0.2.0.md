# PyTradeKit 0.2.0 - OMS & Execution

## Release message

PyTradeKit 0.2.0 introduces the first canonical Order Management System and provider-neutral execution boundary.

This release proves order lifecycle semantics, duplicate protection, uncertainty handling, and race behavior without connecting to a real broker.

## Safety and correctness guarantees

The qualified 0.2 implementation enforces:

- duplicate fill produces one economic effect
- filled quantity cannot exceed order quantity
- FILLED requires complete quantity
- terminal state does not regress from late acceptance
- external order identity cannot silently change
- submit timeout becomes UNCERTAIN rather than FAILED
- cancel timeout becomes UNCERTAIN rather than CANCELLED
- no blind retry is introduced by application use cases
- uncertainty can converge through query_order
- fill may arrive before acceptance
- full fill wins over stale cancellation confirmation

## Explicit limitations

0.2.0 does not include:

- real broker connectivity
- durable database persistence
- process-restart recovery
- portfolio accounting
- risk engine
- strategy runtime
- backtest engine
- HTTP API
- distributed workers
- production operations

These remain later roadmap milestones.

## Upgrade from 0.1.0

0.2.0 preserves the 0.1 domain foundations and adds new bounded package surfaces.

The package root remains intentionally narrow and continues to expose only __version__.
