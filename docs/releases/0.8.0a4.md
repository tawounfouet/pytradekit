# PyTradeKit 0.8.0a4 - IBKR Discovery & Contract Freeze

**Status:** Alpha milestone - LOT-04.

PyTradeKit 0.8.0a4 freezes the first Interactive Brokers implementation envelope before introducing any SDK-backed adapter.

## Added

- dependency-free pytradekit.brokers.adapters.ibkr.discovery package;
- machine-readable IBKRContractFreeze;
- IBKR PAPER and LIVE socket port matrix;
- explicit LIVE-port rejection for PAPER qualification;
- identity role freeze for orderRef, orderId, permId, execId, conId and clientId;
- readiness facts including nextValidId;
- reconnect policy requiring implicit resubmission to remain disabled;
- capability target and deferred-capability inventory;
- canonical contract compatibility decisions;
- explicit unresolved PAPER questions;
- IBKR contract-freeze architecture document;
- IBKR discovery guide;
- LOT-04 qualification document;
- LOT-04 architecture, unit and public-contract tests.

## Contract decisions

- ExecutionPort remains unchanged.
- BrokerSnapshotPort remains unchanged.
- ProviderOrderIdentity remains unchanged with orderRef and permId mapping.
- ProviderFillIdentity.external_fill_id maps to execId.
- ProviderInstrumentIdentity.external_id maps to conId.
- orderId remains adapter-local session state.
- clientId remains runtime connection state.
- nextValidId is readiness and sequencing state, not canonical identity.
- reconnect requires reconciliation before new economic effects.
- the existing Alpaca-only RuntimeProfile is not extended with IBKR branches.

## SDK policy

TWS API 10.49+ is documented by IBKR as GPL.

PyTradeKit remains Apache-2.0.

The official ibapi distribution is not added by LOT-04 pending explicit license review.

ib_async remains a candidate provider implementation and is not added as a dependency by LOT-04.

## No certification claim

0.8.0a4 does not emit IBKR CertifiedCapability.

The first provider-backed certification can only occur after the IBKR ACL, PAPER execution, snapshots, reconciliation and safety integration exist.
