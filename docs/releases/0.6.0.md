## Recovery guarantees

### Missing Fill

A missing broker execution is imported only from stable execution evidence.

The recovery path is:

~~~text
provider execution
-> CanonicalFill
-> ProcessFill
-> OMS
-> Portfolio
-> ProcessedFillRegistry
-> Outbox
-> commit
-> fresh verification
~~~

Qualification proves one provider Fill creates exactly one canonical economic effect.

### Stale correction

A recovery action cannot apply when current durable state has moved beyond the watermark used by the original comparison.

The old correction is rejected and a fresh reconciliation is required.

### Process kill

If a process dies after an economic repair commits but before verification, the active run becomes stale.

Restart closes the stale run, captures fresh evidence, observes the already-applied repair, and does not repeat the economic effect.

### Outbox transaction failure

Fill, OMS, Portfolio, ProcessedFillRegistry, and Outbox changes remain one local transaction.

A commit failure rolls them all back.

A subsequent replay applies one complete effect.

### Reconnect and incident recovery

Starting recovery invalidates prior safe admission evidence.

Transport recovery alone cannot restore readiness.

Only a new completed CONSISTENT/HIGH reconciliation can reopen unrestricted new risk.
