# PyTradeKit 0.8.0a1 - Broker Adapter Contract Candidate

**Status:** Alpha milestone - LOT-01.

PyTradeKit 0.8.0a1 introduces the provider-neutral contract foundations required to prove broker neutrality with a second provider.

## Added

- BrokerCapability taxonomy for P0 and optional broker capabilities.
- CapabilityConstraint and CapabilitySupport for capability-scoped applicability.
- CertificationLevel from C0 DEFINED through C5 LIVE QUALIFIED.
- ProviderCapabilityManifest with immutable provider, environment, SDK, account, asset, order, TIF, session, stream and limitation metadata.
- ContractVersion with BrokerAdapterContract v1 candidate identity 1.0-rc1.
- BrokerContractDimension and BrokerContractInvariant.
- ProviderFixture protocol over existing ExecutionPort and BrokerSnapshotPort.
- Broker compliance architecture documentation.
- FF-048 through FF-056 architecture fitness functions.
- Import Linter protection preventing the compliance core from importing concrete adapters.

## Architecture guarantees

- No concrete provider dependency exists in pytradekit.brokers.compliance.
- Existing canonical ExecutionPort remains unchanged.
- Existing generic BrokerSnapshotPort remains unchanged.
- Provider IDs remain external evidence.
- No Alpaca or IBKR branch is introduced into Domain, OMS, Risk, Portfolio, Reconciliation or Safety.
- The historical 0.5 runtime ProviderManifest remains intact.
- ProviderCapabilityManifest represents claims, not certification.

## Deferred to LOT-02

- ComplianceRequirement.
- ComplianceScenario.
- ComplianceResult.
- ComplianceEvidence.
- ComplianceReport.
- CertifiedCapability.
- ComplianceHarness.
- EvidenceSanitizer.
- CertificationRegistry.

## Provider scope

No IBKR implementation is introduced by this release.

Alpaca remains PAPER-only under the existing qualified runtime contract. LIVE remains unavailable.
