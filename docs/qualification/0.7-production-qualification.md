# PyTradeKit 0.7 Production Qualification

## Purpose

LOT-08 attempts to break the security, safety governance, operations, secrets and deployment controls introduced across PyTradeKit 0.7.

## Qualification surfaces

The dedicated release gate executes:

- authorization negative E2E;
- account and environment scope isolation;
- role-expiry qualification;
- SafetyGate E2E;
- KillSwitch E2E;
- RiskOverride hard-safety and expiry qualification;
- health and readiness E2E;
- stateful alerting E2E;
- telemetry outage E2E;
- secret-provider outage E2E;
- security, safety and health property tests;
- PostgreSQL security and safety persistence;
- PostgreSQL governance concurrency;
- architecture fitness functions;
- static LIVE prohibition checks.

## Known limitations

PyTradeKit 0.7 remains PAPER-focused.

LIVE trading is unavailable by design.

The deployment baseline is single-node. High-availability orchestration is outside 0.7.

The OpenTelemetry integration is an adapter boundary and does not make telemetry infrastructure authoritative for economic state.

ExternalSecretsProvider is provider-neutral. Cloud-specific secret-manager integrations remain deployment adapters.

Broker neutrality with a second provider is deferred to milestone 0.8.
